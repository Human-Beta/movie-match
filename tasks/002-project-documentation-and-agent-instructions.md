# 002 — Project documentation and agent instructions

## Goal

Зробити репозиторій самодостатнім джерелом контексту, щоб розробник або AI-агент міг виконувати задачі, не втрачаючи межі й рішення MVP.

## Scope / Requirements

- Додати в `docs/` актуальні версії продуктових документів проєкту: `vision.md`, `v0.1.md`, `stack.md` та `ideas.md`.
- Зберегти `docs/v0.1.md` головним джерелом істини щодо функціональності поточного MVP.
- Створити короткий кореневий `AGENTS.md` з правилами роботи в репозиторії та посиланнями на `docs/` і `tasks/`.
- Зафіксувати, що новий scope не додається без явного рішення, а майбутні ідеї потрапляють у `docs/ideas.md`.
- Пояснити в `README.md`, що це за продукт, як запустити проєкт і де шукати специфікацію та задачі.
- Не дублювати детальні вимоги між файлами без потреби; використовувати посилання.

## Acceptance Criteria

- Новий учасник може з кореневого `README.md` знайти контекст продукту, специфікацію v0.1, стек і список задач.
- `AGENTS.md` однозначно визначає пріоритет `docs/v0.1.md` і вимагає виконувати критерії конкретного task-файлу.
- Документи не суперечать один одному щодо меж v0.1 та узгодженого стеку.
- Наявні `docs/`, `README.md` або `AGENTS.md` не перезаписані всліпу: корисний вміст збережено й акуратно доповнено.

## Out of Scope

- Зміна продуктової специфікації або додавання нових функцій.
- Деталізація всього backlog наперед.
- Документація API, схеми бази даних чи deployment-процесу, яких ще немає.
- Автоматична синхронізація з зовнішніми документами.

## References / Notes

- Джерелом для `docs/` мають бути чинні Sources проєкту, а не переказ із пам’яті.
- Узгоджений стек: Next.js, React, TypeScript, Tailwind CSS, Supabase Postgres, Supabase Realtime, Drizzle, Zod, Vercel і `pnpm`.
- `tasks/README.md` відповідає за порядок і статус; окремі task-файли — за деталі виконання.
