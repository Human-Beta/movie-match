# 005 — Create and restore TV room

## Goal

Реалізувати початок TV-сценарію: створювати нову кімнату або відновлювати збережену активну кімнату та показувати екран очікування з кодом і QR-посиланням для телефонів.

## Scope / Requirements

- Додати `/tv`, який у браузері перевіряє збережений у `localStorage` room code, а потім відновлює доступну кімнату або створює нову.
- Виконувати перевірку та створення кімнати через валідовану Next.js server boundary і Drizzle. Browser code не має читати чи змінювати продуктову схему через Supabase Data API.
- Вважати кімнату доступною для відновлення, якщо вона існує, має `expiresAt` у майбутньому та не перебуває у стані `closed`. Не змінювати статус простроченої кімнати в цій задачі.
- Генерувати криптографічно випадковий uppercase room code, сумісний із constraint схеми, та обмежено повторювати створення при unique collision. Код не повинен бути послідовним або передбачуваним.
- Після успішної перевірки чи створення зберігати актуальний code в `localStorage` і перенаправляти TV на `/tv/{roomCode}` без циклів або дубльованого створення через повторний render.
- Додати `/tv/{roomCode}` з мінімальним українським waiting UI: room code, абсолютне join-посилання на `/join/{roomCode}`, QR-код цього посилання та початковий статус очікування учасників.
- Вибрати невелику QR-бібліотеку лише для генерації коду; не додавати scanner, зовнішній сервіс або іншу інфраструктуру.
- Для некоректного, неіснуючого, закритого або простроченого прямого URL показувати зрозумілий український стан і дію для створення нової кімнати. Не відновлювати таку кімнату з `localStorage`.
- Додати цільові автоматизовані тести для create/restore-рішень, нормалізації коду та collision retry; UI перевірити щонайменше для успішного й недоступного room state.

## Acceptance Criteria

- Перший перехід на `/tv` створює рівно одну кімнату зі статусом `waiting`, `netflixOnly=false`, `underTwoHours=false`, `yearFilter=any`, без вибраних `roomGenres` і з одногодинним lifetime зі схеми, зберігає її code та відкриває `/tv/{roomCode}`.
- Повторний перехід на `/tv` у тому самому браузері відновлює ту саму доступну кімнату; неактивний збережений code очищається або замінюється новим.
- Конкурентний unique collision не повертає користувачу помилку, доки не вичерпано невелику обмежену кількість спроб, і не створює дубльованих room rows для одного успішного запуску.
- QR-код декодується в абсолютний URL поточного origin з точним шляхом `/join/{roomCode}`, а code залишається читабельним окремо від QR.
- Пряме відкриття недоступної кімнати не показує waiting screen як активний і не переводить її статус у `closed`.
- `anon` і `authenticated` не отримують `SELECT`, `INSERT`, `UPDATE` або `DELETE` на продуктові таблиці; усі database operations проходять server-side через Drizzle.
- Production build, typecheck, lint, format check і додані тести проходять.

## Out of Scope

- Приєднання учасників, participant sessions і room-full logic — задача 006.
- Supabase Realtime, live participant count або connection tracking — задача 007.
- Host filters, seed-фільми, старт гри, раунди та голосування — задачі 008–014.
- Автоматичне переведення простроченої кімнати в `closed` — задача 016.
- Повноцінний візуальний дизайн TV-флоу або deployment.

## References / Notes

- Джерела істини: `docs/v0.1.md`, `docs/stack.md`, `lib/db/schema.ts` і `AGENTS.md`.
- `/tv` залежить від browser-only `localStorage`, але room existence, status і expiration завжди перевіряються сервером.
- Відновлення означає повернення до наявної кімнати незалежно від її майбутнього active state; UI для `playing`, `matched` та `exhausted` додадуть відповідні наступні задачі.
