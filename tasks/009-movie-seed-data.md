# 009 — Movie seed data

## Goal

Наповнити first-party каталог 50–100 вручну підібраними реальними фільмами та дати відтворювану команду seed, щоб фільтри й генерація раундів працювали на узгоджених даних v0.1.

## Dependencies

- Задачі 003–004: database configuration, migrations і таблиці `genres`, `movies`, `movie_genres`.
- Seed надає жанри формі задачі 008 і каталог генератору задачі 010; не залежить від готовності цих UI flows.

## Scope / Requirements

### Каталог

- Підготувати version-controlled, вручну підтримуваний набір із 50–100 реальних фільмів. Не генерувати фактичний каталог через AI, не імпортувати його автоматично та не додавати TMDB/IMDb API integration. Якщо в репозиторії немає підготовленого набору, отримати вручну укладений каталог від власника продукту; seed tooling можна реалізовувати незалежно, але сама задача не завершена без даних.
- Кожен запис має містити стабільну seed identity, українську назву для UI, рік, додатну тривалість у хвилинах, щонайменше один канонічний жанр, вручну виставлений `availableOnNetflix` та optional `posterPath`. Використовувати наявну схему; не додавати поля для рейтингу, опису, watch providers або рекомендацій.
- Мати різноманіття для наявних фільтрів: старі й нові фільми, тривалість нижче та від 120 хвилин, обидва значення Netflix і фільми з кількома жанрами. Не вимагати трьох результатів для кожної комбінації: порожні та малі вибірки є штатним входом задачі 010.
- Уніфікувати жанри й українські назви жанрів, не створювати дублікати через регістр, пробіли або синоніми. Звʼязок фільму з кількома жанрами не дублює сам фільм.
- Постери optional: за відсутності перевіреного придатного asset зберігати `null`, без вигаданого URL. Джерело та умови використання доданих зображень зафіксувати в супровідній документації; fallback UI належить задачі 010.
- Описати англійською походження й порядок ручного оновлення даних, включно з датою та контекстом ручної перевірки Netflix availability. Boolean є curated значенням для v0.1, а не результатом live availability lookup.

### Seed command

- Додати явну команду `pnpm db:seed`, яка використовує наявну server-side database configuration і Drizzle. Не запускати seed автоматично на request, application startup, build або як приховану частину schema migration.
- До writes перевіряти весь input: обовʼязкові поля, межі схеми, унікальні seed identities, коректність genre references, повтори фільмів і звʼязків. Не друкувати connection strings або secrets у діагностиці.
- Виконувати seed атомарно та повторювано: повторний запуск того самого набору зберігає movie/genre IDs, кількість записів і звʼязків. Визначити явну стратегію stable identity, яка розрізняє однойменні фільми різних років і узгоджується з поточними identity columns.
- Оновлювати лише записи й звʼязки, якими керує seed; не використовувати `TRUNCATE`, повну заміну каталогу або неявне видалення записів, вилучених із source file. Не ламати посилання на фільми в наявних раундах і жанри в room filters. Конфлікт identity з чужим записом має завершуватися зрозумілою помилкою без часткових змін.
- Описати англійською в `docs/database.md` порядок `migrate → seed`, необхідне оточення, повторний запуск, оновлення каталогу та вибір цільової БД. Перевірки виконувати в ізольованій локальній БД.
- Таблиці каталогу зберігають RLS і наявні browser restrictions. Якщо обрана стратегія seed вимагає schema change, додати migration, metadata та відповідне оновлення `docs/domain/database-schema.md`.

## Acceptance Criteria

- На чистій БД після migrations і `pnpm db:seed` є 50–100 вручну підготовлених фільмів із валідними полями та genre links.
- Повторний запуск не створює нових копій фільмів, жанрів або звʼязків і не змінює їхні identities.
- Контрольована зміна seed-запису оновлює той самий фільм; сторонні записи, кімнати, room filters і round references зберігаються.
- Невалідний input, конфлікт identity або помилка transaction не залишають частково завантаженого каталогу.
- Є дані для обох year groups, runtime groups, Netflix values і multi-genre filtering; усі фільми мають щонайменше один жанр.
- Постери можна пропускати; кожне надане посилання чи локальний asset перевірено, а його походження задокументовано.
- Документація дозволяє відтворити початкове наповнення та безпечно повторити seed без знання історії цієї задачі.
- `pnpm verify`, перевірки dataset і PostgreSQL seed integration проходять.

## Verification

- Перевірити структуру всього committed dataset, кількість фільмів, дублікати й genre references.
- На ізольованій БД: migrations → seed → snapshot IDs/counts/links → seed повторно → порівняння; окремо перевірити update та rollback.
- Додати fixtures із не-seed записами й room/round references, щоб перевірити, що повторний seed не змінює чужі дані та не порушує зовнішні ключі. Після тесту прибрати fixtures.

## Out of Scope

- Автоматичні imports, scraping, AI-generated movie data, автоматична перевірка Netflix або сторонній catalog service.
- Admin UI, movie search UI, рекомендації, рейтинги й додаткові продуктові поля.
- Генерація раундів і відображення карток — задача 010.
